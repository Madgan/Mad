# SIS 职业字段 + 同行排行开关：Claude Code 执行指令

> 用法：在 SIS 主程序的仓库里开 Claude Code，把下面「指令」整段贴进去。

---

## 指令

在 SIS（sistudio.app）里做两件事：

**A. 「职业」字段。** 用户注册时必须选择，之后可以在个人资料里改。用途有三个：

1. 统计各职业有多少用户在用 SIS。
2. 3D 虚拟办公室按职业布置用户的私人办公室。
3. 记录转行，看用户的职业怎么变化。

**B. 「同行接单排行」开关。** 排行只显示接单数，不显示金额。用户自己决定要不要上榜，默认不上榜（第 7 点）。

**开始前先做这一步，不要猜：** 先看懂这个仓库用什么框架、数据库、登录方式，以及注册页和个人资料页在哪里。用 5 行以内告诉我你的理解和打算怎么改，等我确认后再动手。

### 1. 职业选项（固定写法，前后端和虚拟办公室共用）

| key | 显示名 |
|---|---|
| `photo` | 摄影师 |
| `video` | 摄像 / 剪辑 |
| `makeup` | 化妆师 |
| `stylist` | 服装造型 |
| `producer` | 制片 / 统筹 |
| `other` | 其他（另外填写文字） |

- key 只能用上面 6 个，统计和办公室都靠 key 识别，显示名以后可以改。
- 把这个列表放在一个共用的地方（一个常量文件或一张表），不要在多个页面各写一份。

### 2. 数据

在用户表（或 profile 表）加：

- `job`：文字，只允许上面 6 个 key。
- `job_other`：文字，最多 20 个字，只有 `job = 'other'` 时才有值。
- `job_updated_at`：时间。

另外新增一张转行记录表 `user_job_history`，包含 `user_id`、`from_job`、`to_job`、`changed_at`。每次改职业写一笔，注册时也写一笔（`from_job` 为空）。

**老用户：** `job` 先留空，不要给默认值，否则统计会被污染。他们下次登录时弹一个只出现一次的选择框，必须选完才能继续。

### 3. 注册页

- 加「职业」，必填，用按钮选择，不用下拉。
- 选「其他」时出现文字框：「你的职业，例：灯光师」，此时必填。
- 下面加一行小字：「你的私人办公室会按职业布置。之后可以在个人资料里更换。」

### 4. 个人资料页

- 显示目前的职业，可以直接改，规则跟注册页一样。
- 保存后写转行记录，并更新 `job_updated_at`。
- 成功提示：「职业已更新，办公室摆设会跟着换」。

### 5. 接口（虚拟办公室会调用）

- 取当前用户资料的接口（例如 `GET /me`）要回传 `job` 和 `job_other`。
- 改资料的接口（例如 `PATCH /me`）要接受 `job` 和 `job_other`。后端要检查 key 是否合法，选 `other` 时 `job_other` 不能空，其他职业时把 `job_other` 清空。
- 虚拟办公室的 `SIS.profile()` 和 `SIS.setJob()` 会直接对接这两个接口。字段名用 `job` 和 `job_other`，不要改名。

### 6. 统计（管理员可见）

做一个只有管理员能看的统计（一个页面，或先给一组 SQL 也可以）：

1. 各职业人数和占比，没填的单独算一行「未填写」。
2. 「其他」里大家填的文字，按出现次数排序，用来决定要不要新增职业选项。
3. 每月新注册用户的职业分布。
4. 转行次数：从哪个职业转到哪个职业，各多少人。

Postgres 参考：

```sql
-- 各职业人数
select coalesce(job, '未填写') as job, count(*) as users,
       round(100.0 * count(*) / sum(count(*)) over (), 1) as pct
from users group by 1 order by users desc;

-- 「其他」里填写的职业
select job_other, count(*) from users
where job = 'other' and job_other is not null
group by 1 order by 2 desc limit 30;

-- 转行流向
select from_job, to_job, count(*) from user_job_history
where from_job is not null group by 1, 2 order by 3 desc;
```

### 7. 同行接单排行（默认不上榜）

排行在虚拟办公室的数据大屏里显示：每月按接单数排名，每一行显示名字、工作室名、单数，**任何地方都不显示金额**。

**数据：**

- 用户表加 `show_in_ranking`：布尔值，默认 `false`。老用户也是 `false`，不要替他们打开。
- 接单记录：先找 SIS 里有没有记录接单的地方。如果没有，新增 `job_logs` 表，包含 `id`、`user_id`、`project`（文字）、`amount`（金额）、`client`（可空）、`created_at`。
  - 虚拟办公室的「接单钟」会写入这张表。
  - `amount` 和 `client` 只有本人看得到，任何回传给别人的接口都不能带这两个字段。

**个人资料页：**

- 加一个开关：「在同行接单排行显示我」，默认关闭。
- 开关下面的小字：「只显示你的名字和本月接单数，不会显示金额。可以随时关闭。」
- 关闭后，排行马上看不到这个人。

**接口：**

- 排行接口（例如 `GET /ranking?month=2026-11`）只回传 `show_in_ranking = true` 的用户，每一行只有 `name`、`studio`、`job`（职业 key）、`jobs`（单数），最多 20 名，按单数从多到少排序。
- `month` 可以传过去的月份，用来看月度回顾（虚拟办公室会显示本月和前两个月）。
- **上榜开关以「现在」为准：** 用户关掉开关后，过去月份的排行也不能再出现他，不要存每个月的排行快照。
- `GET /me` 加回传 `show_in_ranking`，`PATCH /me` 接受修改它。
- 本人的金额统计（本月接单额等）另外用一个只回传自己数据的接口，不要放进排行接口。

```sql
-- 本月排行：只算有打开开关的人
select u.name, u.studio, count(*) as jobs
from job_logs j join users u on u.id = j.user_id
where u.show_in_ranking = true
  and j.created_at >= date_trunc('month', now())
group by u.id, u.name, u.studio
order by jobs desc
limit 20;
```

**月度回顾：** 看过去的月份时，虚拟办公室会从排行结果里挑出每个职业（`other` 除外）接单最多的人，显示成「10 月回顾 · 各职业接单最多」。这一步在前端算，后端只要回传 `job` 字段就够了，不用另外做接口。

### 验收

- [ ] 新用户不选职业无法完成注册；选「其他」不填文字也无法完成注册。
- [ ] 老用户登录会被要求选一次职业，选完不再出现。
- [ ] 个人资料改职业后，`GET /me` 立即回传新值，转行记录多一笔。
- [ ] 送不合法的 key 给后端，会被拒绝。
- [ ] 管理员能看到第 6 点的四项统计，一般用户看不到。
- [ ] 新用户和老用户的 `show_in_ranking` 都是 `false`，排行一开始是空的。
- [ ] 打开开关后，这个人出现在排行，关掉后立刻消失。
- [ ] 排行接口的回传里找不到 `amount`、`client` 或任何金额字段（直接看接口原始回传确认）。
- [ ] 传上个月的 `month`，回传的是那个月的单数；关掉开关的人在过去月份也不会出现。
- [ ] 没有改动其他字段，也没有改到其他页面。
